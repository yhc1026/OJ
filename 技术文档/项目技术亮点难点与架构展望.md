# OJ-Ssystem 技术亮点、难点与架构展望

> 面向评审/汇报：提炼 **3 个技术亮点**、**3 个技术难点**、**3 个未来架构改进方向**。  
> 依据当前仓库实现（Spring Boot 3、Spring Cloud Alibaba、Gateway、Nacos、MySQL、Redis、RabbitMQ、Elasticsearch、Docker 判题等）。

---

## 一、三个技术亮点

### 1. 容器化判题与链路的异步解耦（RabbitMQ）

- **现象**：`oj-friend` 接收提交后在表 `tb_friend_code_submit`中预创建记录并写入，将 **判题消息** 发往 RabbitMQ；`oj-judge` 侧 `@RabbitListener` 消费并通过容器池创建容器，后调用 `JudgeRunService` 在容器中完成编译、运行、比对。
- **价值**：一方面隔离机制隔离恶意代码，保证jvm运行的安全性；同时提交接口快速返回，判题耗时与吞吐由 **判题服务 + 队列** 承担，避免同步 HTTP 压垮 friend 或长连接超时。

### 2. 阿里云OSS存储逻辑的优化

- **现象**：数据库存储图片的全量路径，如果前端被劫持，可能会出现存储有害路径的情况，损害用户的隐私权
- **优化1**：将路径前缀通过配置的形式写死，数据库只存储 **object key** （路径后缀），通过如果需要查询图片路径，通过拼接的方式得到完整的路径
- **价值1**：优化1可以解决如果前端被劫持，也只能在指定前缀的目录中作乱，无法跳转到更危险的链接
- **优化2**：禁止使用主用户的权限，通过创建RAM用户并严格控制权限，比如限制到目标 bucket 的指定前缀（如 oj/avatar/*）
- **价值2**：优化2可以解决前端权限过大导致如果被劫持，损害OSS中存储的各种信息

### 3. 检索与读题分层：Elasticsearch/Redis + MySQL 回源

- **现象**：对题目/竞赛/用户检索 **先 ES/Redis、空则 MySQL**，并 **同步回填，单条同步 ES/Redis**
- **价值**：倒排索引擅长标题/模糊类查询、缓存查询效率高；MySQL 保持用于维护权威数据和查询兜底；ES/Redis 作为 **加速层**，与判题读题路径结合，减少热点 SQL。

## 二、三个技术难点

### 1. 不可信代码的执行安全与资源边界

- **难点**：用户代码可能死循环、爆内存、读写敏感路径或滥用进程；需在 **CPU/内存/时间/文件系统/网络** 等维度限界。
- **现状依赖**：Docker 隔离、`tmp-judge` 独立工作目录、题目侧 `timeLimit`/`spaceLimit` 等参与判题参数传递；更细粒度还需结合镜像、seccomp、cgroup 等与运维策略（参见《OJ判题系统安全技术文档》）。

### 2. ES 与 MySQL 的语义一致与延迟

- **难点**：ES 非强一致存储；当前以 **回源 + 回填** 为主，管理端若改题未同步 ES，可能出现 **短暂旧数据或检索空窗**。
- **影响面**：检索结果、判题读题路径均可能读到滞后副本；需从产品设计或同步链路上接受 **最终一致** 或补齐 **写路径双写**。

### 3. 异步判题下的状态与用户体验

- **难点**：提交后立即返回 `PENDING`，用户依赖 **轮询/查询结果接口**（如按 `submitId` 拉状态）；需处理 MQ 堆积、判题失败、 poison message（项目中有 DLX 相关常量，需与运维策略结合）。
- **关联**：判题服务扩缩容、队列监控、失败重试与 **死信** 处理若不完善，易出现长时间 `PENDING` 或结果不一致感知。

## 三、三个未来架构改进点

### 1. 判题平面水平扩展与队列治理

- **方向**：多实例 `oj-judge` 并发消费；按题目难度/耗时 **分队列或优先级**；判题机资源与队列长度 **联动弹性**。
- **收益**：高峰时稳定 RT；避免单点判题机成为瓶颈。

### 2. 数据同步与搜索/读题一致性策略产品化

- **方向**：管理端题目/竞赛变更时 **同步写 ES**、或 **Canal/Debezium** 订阅 binlog、或 **定时校验对账**；对强一致场景提供 **版本号** 或 **读主库回退** 策略。
- **收益**：减少「搜不到题」「判题读到旧题面」的边界客诉。

### 3. 可观测性与运维闭环

- **方向**：网关—friend—MQ—judge 全链路 **TraceId**；判题耗时、队列积压、DLQ 率、沙箱失败原因 **指标与告警**；关键表状态机可视化。
- **收益**：快速定位「卡在 PENDING」「某类 CE 暴增」等问题，缩短 MTTR。
